# Proj0055: Enable nullability analysis for C#
In C# 8.0 and later, [nullability analysis](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/nullable-reference-types)
provides compile-time checks to ensure reference types are safely handled,
helping to avoid `NullReferenceException` at runtime.

By leaving nullability analysis disabled or not defining it, reference types
are considered nullable by default but without any compiler warnings when null
is dereferenced or assigned incorrectly.

## Migrating existing projects
Turning the feature on for an old codebase can immediately generate hundreds or
thousands of compiler warnings. Fixing these blindly often leads to introducing
subtle runtime bugs. You should not ignore the feature entirely. The best
approach for old projects is a gradual, pragmatic adoption strategy.

### 1. Adopt a *Pay-As-You-Go* Strategy (File-by-File)
Enable analysis in the specific files you are actively working by setting
`#nullable enable` at the very top of a file when you are fixing a bug or
adding a feature to it. Only fix the warnings within that single file.

### 2. Prioritize Your Public API and Data Models
If the project is a shared library or has a core data layer (like EF Core
models), migrate those files first.Annotating your data models immediately
clarifies what the database expects.Annotating public methods protects the
boundaries of your old system from new code.

### 3. Use the Null-Forgiving Operator (!) Defensively
When migrating old code, if you see a warning but the code has run fine in
production for five years, do not rewrite the logic. Simply apply the `!`
operator to tell the compiler: "This works, leave it alone."

```csharp
// Old code that is proven to work
string value = GetLegacyData()!;
```

In all scenario’s you set the global project setting to `<Nullable>annotations</Nullable>`.

## Non-compliant

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
  </PropertyGroup>

</Project>
```

Or:

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>disable</Nullable>
  </PropertyGroup>

</Project>
```

## Compliant

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>
```
